# AI 慕课学伴 项目宪法

## 核心原则

### 一、效果优先，成本可控

在效果相近的前提下选择成本更低的方案。优先使用本地模型处理高频任务（音频转写、OCR），仅在必要时调用付费视觉或语言模型。所有外部模型必须通过配置可切换，避免供应商锁定。

### 二、用户数据本地优先

用户上传的视频、提取的帧、转写文本、向量索引等核心数据默认保存在本地。向外部 API 发送的数据应限于当前课程处理所必需的最小内容，禁止上传无关信息。

### 三、中文课程优先优化

系统针对中文慕课场景设计。OCR、ASR、LLM 和嵌入模型必须对中文内容有良好支持。界面默认使用简体中文，术语表达符合中文技术学习者习惯。

### 四、简洁可维护

优先采用简单、可理解的实现方案。避免过度工程和过早优化。每个模块职责单一，接口清晰，便于后续替换 OCR、视觉模型或 LLM。

### 五、可测试与可演示

核心处理链路必须可端到端验证。每个用户故事交付后应能独立演示。保留示例测试视频和预期输出，方便回归验证。

### 六、渐进式交付

按用户故事优先级分阶段实现，每个阶段交付一个可独立运行和验证的增量。MVP 优先完成“上传视频 → 总结 → 问答”主链路，后续再补充 URL 下载、复习清单、跨课程问答等扩展。

## 附加约束

- 优先支持 macOS 和 Linux，Windows 兼容作为尽力而为。
- 用户配置通过项目根目录 `.env` 管理，支持环境变量覆盖。
- 代码异常必须记录日志，禁止静默吞掉异常。
- 数据库查询优先在 SQL 层完成过滤，避免拉回大量行再用 Python 计算。
- 前端使用 Next.js 现代前端，保留 Streamlit 作为可选兼容层。
- 新增功能同步更新相关规格、任务和 quickstart 文档。

## 开发流程

- 所有规格、计划、任务文档使用中文编写。
- 实现前确保对应任务和测试已明确。
- 每次提交应包含一个逻辑完整的小改动。
- 发布前必须通过 `quickstart.md` 中的端到端验证。

## 下一版本边界（2026-07-27 确认）

下一版本聚焦学生用户的基础体验优化，不包含新 AI 能力：

1. **前端模型/API 配置页面**：提供默认模型，学生无需手动编辑 `.env` 即可配置 API Key 和选择模型。暂不需要权限验证。
2. **导航与入口优化**：明确区分“课程库”（管理上传）、“全局搜索”（跨课程提问）、“开始学习”（单课程学习 + 内置问答）。移除重复入口。
3. **一键启动脚本**：提供单个命令同时启动后端和前端并打开浏览器，降低非技术用户门槛。
4. **桌面 App**：延后到下下版本或更晚，下一版本不实现。

## 产品原则补充

- 面向学生，默认配置必须齐全，操作路径简单直接，不让学生花费时间在环境、命令行或模型选择上。
- 页面入口职责单一，避免功能重复导致困惑。
- 自动化能替代手动步骤的，优先自动化。

## 治理

本宪法优先于其他开发实践。任何修改需记录理由并同步更新相关文档。所有拉取请求和代码审查必须验证是否符合本宪法。
