## 一、技术选型类

### Q1：为什么第一版用 Streamlit，后面又换成 Next.js 14？

**002 spec 明确记录**：

> "Streamlit 适合快速验证，但难以提供精致的 AI 产品体验。新增 Next.js 前端可显著提升品牌感，同时保留 Streamlit 作为故障回退。"

具体痛点在 002 User Story 中有说明：
- 视频播放需要流式修复（"浏览器无法直接播放本地路径"）
- 需要"更现代、更美观、交互更流畅的 Web 界面"

**不是预设策略，而是验证后的自然演进**。

---

### Q2：为什么用 SQLite 不用 PostgreSQL/MySQL？

**004 spec 背景**：

> "当前需分别启动后端 `run.py` 和前端 `npm run dev`，对非技术学生门槛过高。"

**设计目标**：降低使用门槛。SQLite 单文件零运维，配合 004 的"一键启动"脚本，让非技术用户也能跑起来。

---

### Q3：混合检索相比纯向量检索好在哪？

**002 spec User Story**：

> "混合检索提升 RAG 问答质量，全局搜索解锁'在所有已学课程中提问'的高阶场景"

> "用精确关键词提问时，混合检索能召回向量检索遗漏的内容"

**真实痛点**：向量检索对精确关键词不敏感，BM25 补充，RRF 融合。

---

### Q4：Playwright 做联网搜索，为什么不用搜索引擎 API？

**006 迭代一新增功能**（specs 中无独立文档，在 005 plan 的"第三迭代"中提及）。

真实原因：
- 免费搜索 API 不存在
- Playwright 驱动真实浏览器，抗反爬

**用户价值**：回答附"网络参考"区，来源可追溯。

---

### Q5：为什么做多模型配置？

**002 spec User Story**：

> "学习者希望为总结、问答、视觉理解分别配置最合适的模型"

> "多模型配置让系统在不同任务上取得成本与效果平衡"

**用户场景**：不同任务用不同模型，比如总结用便宜的，问答用效果好的。

## 二、算法与实现类

### Q6：SM-2 间隔重复算法是怎么实现的？

**005 spec**：

> 闪卡复习："简单三档标记（认识/模糊/不认识），SM-2 间隔重复留后续"

**006 迭代一实现**：
- ease（难度系数，初始 2.5）
- interval（间隔天数）
- due_date（到期时间）
- quality 0-5 评分驱动调度

**用户价值**：只复习到期的卡片，不用每天翻全部。

---

### Q7：RAG 引用角标是怎么保证准确的？

**真实踩坑**（git 历史）：

> "引用堆砌 [1][2][3][4][5]" → 后端 `_cap_consecutive_citations` 硬截断 ≤3

**实现**（代码可查）：
- LLM 标 [MM:SS] 时间戳
- 后端映射稳定 [N] 序号
- 正文 [N] = 来源第 N 条

**设计意图**：来源可追溯，防止 LLM 编造。

---

### Q8：faster-whisper 怎么防止幻觉？

**真实实现**（代码可查）：
- VAD（语音活动检测）跳过非语音段
- 禁用上下文传递（condition_on_previous_text=False）
- OpenCC 繁→简转换

**002 spec**："处理速度直接影响首次使用体验"，所以用 int8 量化加速。

---

### Q9：测验题是 LLM 生成的，怎么保证质量？

**005 spec**：

> "题型：第一版只做选择题 + 判断题（可自动判分）；简答题留到后续迭代（需 LLM 判分）"

> "解决'看完就忘、不知道自己掌握没'的最高频痛点"

**实现**：
- LLM 生成结构化 JSON（题干、选项、答案、解析）
- 后端 schema 校验
- 判分直接比对选项，不依赖 LLM

## 三、工程与挑战类

### Q10：faster-whisper 在 CPU 上很慢，怎么解决？

**002 spec**：

> "学习者上传 45 分钟课程后，不希望等待 10-20 分钟才能完成处理"

**优化**（002 US2 帧处理加速）：
- 智能视觉调用（OCR 能解决的不用视觉模型）
- 并行 API 调用
- 场景变化抽帧

**后续优化**（git 历史）：
- 断点续传：重新处理复用 ASR 字幕

---

### Q11：项目最大的技术挑战是什么？

**真实踩坑**（git 历史 + 展示页）：

1. **字幕重复显示**：浏览器 controls+track 渲染两次 → track hidden + JS 自绘
2. **联网搜索卡死 90 秒**：Playwright sync 在 FastAPI 线程池 event loop 冲突 → 子进程隔离
3. **重新处理等 40 分钟**：`_clear_old_course_data` 清掉 ASR 字幕 → 断点续传

**每个坑都有真实的用户痛点**。

---

### Q12：AI 参与开发到什么程度？

**speckit 流程**（specs/ 目录结构）：
- spec → plan → tasks → 实现
- 文档入仓，决策有据

**人工审核**（git 历史）：
- AI 误删 `@router.get` 装饰器 → 人工发现修复
- 141 个后端测试自动跑

**模式**：人决策（范围/选型/视觉），AI 执行（代码细节）。

## 四、用户体验优化类

### Q13：除了核心功能，你还做了哪些用户体验优化？

**003 spec（学生体验优化）**：

> "当前配置门槛过高，非技术学生无法独立完成" → 前端模型/API 配置页面

> "大视频处理时间长，用户需要进度反馈，减少焦虑" → 课程处理进度条可视化

> "学习是持续过程，学生需要回顾之前的问题和答案" → 问答历史统一保存

> "答案可读性直接影响学习体验" → Markdown 渲染

> "答案与视频联动是核心学习场景" → 视频跳转与时间戳去重

> "当前处理是黑盒，用户无法判断 ASR/OCR 是否准确" → 诊断可视化页

**004 spec**：

> "用户只想针对某几门课学习" → 多课程学习集

> "对非技术学生门槛过高" → 一键启动脚本

**005 spec**：

> "看完就忘、不知道自己掌握没" → 测验生成 + 闪卡

> "把 AI 从'问答机器'升级为有外形、有动作、有语音、有口头禅的可视化学伴" → 咕咕嘎嘎学伴

### Q14：为什么做可拖动学伴？

**005 spec User Story G**：

> "这是'AI 学伴'定位的灵魂"

> "把 AI 从'问答机器'升级为有外形、有动作、有语音、有口头禅的可视化学伴"

> "支持多角色切换（未来可加 Doro 等更多角色）"

### Q15：离线模式是怎么考虑的？

**真实实现**：
- faster-whisper 本地 ASR
- Chroma 本地向量索引
- SQLite 本地存储
- edge-tts 本地合成（需联网调 API，但模型配置可换本地）

**003 spec 背景**：
> "诊断可视化页"让用户能看清 ASR/OCR 是否准确，不依赖外部服务。

## 五、产品与规划类

### Q16：这个产品和直接用 ChatGPT 传课件有什么区别？

**001 spec**：

> "Users upload local course videos"（本地视频，不上传云端）

> "answers knowledge questions via a RAG agent with timestamp and key-frame references"（时间戳 + 关键帧引用）

**005 spec**：

> "差异化在'主动学习'环节——测验、闪卡、间隔重复"

**核心差异**：
1. 本地处理，隐私安全
2. 视频原生（时间戳跳转、关键帧）
3. 主动学习闭环（测验/闪卡/错题本）

---

### Q17：后续规划是什么？

**005 spec 明确留到 006**：
- 学伴主动关心（"要不要测两道巩固"）
- 闯关 / 等级体系
- 实时语音连续对话
- 简答题 + LLM 判分
- 闪卡 SM-2 间隔重复复习队列（已在 006 迭代一实现）

**005 spec 明确不做**：
- 音频播客讲解（NotebookLM 式，中文 TTS 双人对话不成熟）

**006 迭代一已实现**：
- SM-2 间隔重复
- 视频链接导入
- 网络查询

## 真实踩坑列表（git 历史可查）

1. 课程详情 405「课程不存在」：Edit 误删 `@router.get`

7. 重新处理又等 40 分钟：`_clear_old_course_data` 清掉 ASR 字幕
8. 切错题本做题记录丢：onSuccess 只刷新错题本
9. 错题"已掌握"反复横跳：答对一次就标掌握
10. 切 Tab 作答进度丢失：本地状态未同步服务端
11. 课程列表 SSR 闪跳：服务端渲染与客户端 hydration 不一致
12. HuggingFace 模型下载失败：国内网络超时
