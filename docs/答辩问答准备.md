## 一、技术选型类

### Q1：为什么第一版用 Streamlit，后面又换成 Next.js 14？

这是刻意的两阶段策略。初期重点是验证 AI 管线是否可行，Streamlit 让我把精力集中在后端逻辑上。但验证通过后，**我站在用户角度体验了学习流程**：Streamlit 每次点击整页刷新，看视频时页面一刷新播放位置就丢了；学伴无法拖动；测验作答切个 Tab 进度就没了。这些都是真实伤害学习体验的问题，所以 002 版本迁移到 Next.js 14。技术选型不是追新，而是用户场景驱动。

### Q2：为什么用 SQLite 不用 PostgreSQL/MySQL？

产品定位是本地个人学习工具。我设想的目标用户是大学生或职场学习者，他们**不是程序员，不可能装 PostgreSQL**。SQLite 单文件零运维，下载双击就能跑，备份就是复制一个文件。技术服务于用户门槛，而不是反过来。

### Q3：混合检索相比纯向量检索好在哪？

纯向量对精确关键词不敏感。比如用户问"ease 因子怎么更新"，向量可能召回语义相近但不含答案的段落。**从用户视角看，他问一个具体术语，却得不到准确答案，会立刻不信任这个工具**。BM25 补关键词召回，RRF 融合，保证术语类问题也能命中。学习工具的信任一旦失去就很难挽回。

### Q4：Playwright 做联网搜索，为什么不用搜索引擎 API？

免费 API 没有，付费 API 对一个开源学习项目不现实。Playwright 驱动真实浏览器，结果和真人搜索一致。代价是慢几秒，但**学习场景下，用户等几秒拿到有来源标注的答案，比秒回一个可能编造的答案更有价值**。

### Q5：为什么做多模型配置，不绑定一个 LLM？

不同用户有不同条件：有的有 OpenAI 额度，有的只有国内 API，有的想跑本地模型。多模型配置让用户**根据自己的网络环境和预算选择**，不被单一供应商锁定。这也是本地优先理念的延伸——用户有选择权。

## 二、算法与实现类

### Q6：SM-2 间隔重复算法是怎么实现的？

核心是 ease、interval、due_date 三个字段，用户评分驱动间隔调度。记得牢的卡片间隔越来越长，记不住的频繁出现。**从用户角度，这意味着复习时间花在刀刃上**——不用每天翻几百张卡，只复习到期的。这是 Anki 验证过的成熟方案，我把它内置到产品里，用户不用懂算法也能受益。

### Q7：RAG 引用角标是怎么保证准确的？

最初让 LLM 直接标 [1][2][3]，它会标错位。**想象一个学生在考试前看 AI 总结，引用错了源，他可能学错知识点**——这对学习产品是不可接受的。所以改成后端映射：LLM 标时间戳，后端映射稳定序号，正文 [N] 严格等于来源第 N 条。还加了硬截断防止引用堆砌。**准确优先于炫技**。

### Q8：faster-whisper 怎么防止幻觉？

Whisper 在静音段会编造文本。我用了 VAD 跳过非语音段 + 禁用上下文传递。**为什么较真这个？因为转写文本是后续所有功能（总结、问答、出题）的地基**，地基错了上面全错。用户基于错误的转写学习，后果不堪设想。另外接 OpenCC 做繁简转换，因为很多港台课程视频转出来是繁体，**简体用户看着累**。

### Q9：测验题是 LLM 生成的，怎么保证质量？

判分不依赖 LLM，直接比对选项，100% 准确。错题连续答对 2 次才标掌握——这是踩过坑的：答对 1 次可能是蒙的，状态反复横跳，**用户看到自己的掌握状态跳来跳去，会觉得这个系统不靠谱**。2 次确认消除了抖动，给用户的反馈才可信。

## 三、工程与挑战类

### Q10：faster-whisper 在 CPU 上很慢，怎么解决？

承认这是最大瓶颈，一小时视频要转几十分钟。但**关键是用户不需要干等**：后台异步处理，上传后可以做别的事，处理状态实时可见；断点续传保证失败重试不用从头再来。**我不能让 CPU 变快，但我可以让等待变得可接受**。这是工程上"缓解"和"解决"的区别。

### Q11：项目最大的技术挑战是什么？

三个印象最深的，都是从用户反馈倒推回来的：
1. **字幕重复显示**——用户看视频两行字幕重叠，根本没法看。track hidden + 自绘解决。
2. **联网搜索卡死 90 秒**——用户点了搜索，页面像死了一样。子进程隔离解决。
3. **重新处理等 40 分钟**——用户改个设置重跑，又要等一遍。断点续传解决。

每个坑背后都是一个真实的用户痛点。

### Q12：AI 参与开发到什么程度？会不会是 AI 写的你不懂？

模式是"人决策、AI 执行"。需求、选型、UI 都是我定的；AI 写细节。关键是机器验证 + 人工审核：141 个后端测试自动跑，我还要真机操作看效果。**AI 改代码误删过路由装饰器，是我审查发现的**。没有人工审核，AI 代码不敢直接上——这对用户负责。

## 四、用户体验优化类

### Q13：除了核心功能，你还做了哪些用户体验优化？

很多细节都是围绕"学习场景"打磨的：

**减少等待焦虑：**
- 视频流式播放：大视频不用等下载完，边下边看
- 后台异步处理：上传后可以做别的事，处理状态实时可见
- 断点续传：失败重试不用从头再来

**减少操作摩擦：**
- 课程卡片状态细化：一眼看清"处理中/已完成/失败"，不用点进去猜
- SSR 预取：页面秒开，不闪白屏
- 知识问答页首屏直接显示课程选择器，少点一步
- 笔记/书签删除按钮常驻 + 乐观更新：操作即时反馈，不用等刷新

**沉浸式学习：**
- 视频全屏 + 字幕开关：专注模式
- 学伴可拖动：不挡内容，随时陪伴

**数据驱动：**
- 诊断可视化：学习数据生成薄弱点分析
- 学习周报：周期性复盘，看见自己的进步

这些细节单看都不起眼，但叠加起来，用户会觉得"这个工具懂我"。

### Q14：离线模式是怎么考虑的？

模型全部本地化：faster-whisper 本地 ASR、Chroma 本地向量索引、SQLite 本地存储。**用户在图书馆、自习室、飞机上，没网也能学**。这对学习场景很重要——网络不稳定不应该成为学习的障碍。

### Q15：为什么做可拖动学伴？不觉得是噱头吗？

不是噱头，是情感化设计。学习是孤独的，有个可拖动的形象陪着，**能降低学习的枯燥感**。而且学伴不只是装饰——答对答错有不同情绪反应，能语音播报，这些是正向反馈机制。教育产品不只是功能堆砌，情感陪伴也是价值。

## 五、产品与规划类

### Q16：这个产品和直接用 ChatGPT 传课件有什么区别？

三个差异，都围绕学习场景：
1. **隐私**：课程视频不出本机。很多用户学的是公司内部培训材料，传 ChatGPT 有合规风险。
2. **视频原生**：时间戳跳转、字幕、笔记书签都围绕视频设计，ChatGPT 处理不了视频。
3. **学习闭环**：不只是"问到"，而是"学会"——测验、闪卡、错题本、间隔重复、连续学习统计，形成完整的学习回路。ChatGPT 答完就完了，我的产品管你忘没忘。

### Q17：扩展性如何？

定位个人学习库，SQLite 几百门课没问题。**而且个人场景下，一个人同时学几十门课已经很罕见了**，这个容量对目标用户是过剩的。

### Q18：后续规划是什么？

几个方向，还是从用户痛点出发：
- **实时语音对话**：打字提问打断学习心流，语音更自然
- **简答题判分**：选择判断只能考记忆，简答才能考理解
- **学伴主动关心**：现在学伴是被动的，未来可以主动提醒"你这张卡该复习了"，更像真实的学伴
