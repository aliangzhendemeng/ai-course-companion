# Spec: 项目展示静态站（showcase-site）

## 目标

为「AI 慕课学伴」项目构建一个**独立静态展示站**，面向技术面试/评审，讲清楚三件事：
1. **成果展示**——做了什么、功能演进、亮点
2. **技术方案**——架构、技术栈、关键模块、数据流
3. **AI 开发方法**——speckit 流程 + Claude Code 人机协作做产品的经验

不仅讲"怎么做"，更要讲**"为什么这么做、为什么不用别的方案、踩了什么坑、怎么解决"**。

## 范围

### 做
- **Astro** 静态站（静态优先、组件化、Markdown 写内容），部署 GitHub Pages
- 首屏 landing（抓眼）+ 内页文档（详实，技术深度）
- **Playwright 自动截图/录屏脚本**：自动生成功能演示素材（截图 + GIF），无需手动录屏
- 内容板块：概览 / 成果展示 / 技术方案 / AI 开发方法 / 设计决策（为什么）/ 踩坑与解决 / 后续规划
- 内容源自真实开发全程（决策、bug、取舍均有据可查）

### 不做（本范围外）
- 不连后端做现场真交互（用录屏/GIF 演示；面试真 demo 用本地完整项目）
- 不做 i18n、不做用户系统、不做 SEO 深度优化（静态站天然 SEO 友好即可）

## 用户故事

- **US1 首屏抓眼**：作为面试官，打开站点 5 秒内理解"这是什么、价值何在、亮点在哪"，被吸引往下看
- **US2 成果一目了然**：看到功能全貌（按版本演进 001→006）、关键功能演示（录屏/截图）、量化的亮点
- **US3 技术方案清晰**：看到架构图、技术栈、关键模块（混合检索 RAG / faster-whisper ASR / PaddleOCR / SM-2 / 会话制 / Playwright 子进程 / 联网搜索）、数据流
- **US4 设计决策有说服力**：关键选型都讲"为什么"——为什么 faster-whisper 不用 API ASR、为什么引用角标后端映射、为什么 Playwright 子进程、为什么字幕 custom 渲染、为什么断点续传…
- **US5 踩坑真实可信**：真实 bug 案例（课程路由误删、SM-2 迁移 NULL、字幕渲染两次、deepseek 503、yt-dlp SSL、reload 卡死…）+ 根因 + 解决
- **US6 AI 开发方法论**：speckit 流程、Claude Code 人机协作模式、怎么用 AI 高效做产品（含经验/教训）

## 设计原则

- **真实 > 包装**：所有"为什么/坑"都是真实发生的（有据可查），不编造
- **信息密度**：技术面试/评审看，重深度（架构图、代码片段、对比表）
- **视觉**：首屏 landing 抓眼（大标题/动效/卡片），内页文档详实（排版/图表/代码块）
- **自包含**：静态站部署 GitHub Pages 即可看（录屏/GIF 内嵌），不依赖后端

## 技术上下文

- **Astro**（静态站点生成，组件化，Markdown 内容）
- 部署 GitHub Pages（或任意静态托管）
- **Playwright**（Python，项目已装）自动生成截图/GIF 素材
- 内容 Markdown + Astro 组件（架构图用 SVG/HTML，代码块高亮）

## 验收

- Astro 静态站构建通过（`astro build`），可部署 GitHub Pages
- Playwright 脚本跑一次，自动生成各功能截图 + GIF，嵌入站点
- 三目标（成果/技术/AI方法）+ 为什么/坑 板块齐全，内容真实
- 面试官视角：5 秒懂价值，10 分钟看完技术深度
