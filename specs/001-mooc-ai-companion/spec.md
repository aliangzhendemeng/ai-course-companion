# Feature Specification: AI 慕课学伴

**Feature Branch**: `001-mooc-ai-companion`

**Created**: 2026-07-23

**Status**: Draft

**Input**: User description: "Build an AI companion for MOOC learning. Users upload local course videos. The system extracts audio, transcribes speech, samples key frames, performs OCR and visual understanding, then generates three-level summaries (outline, abstract, lecture notes) and answers knowledge questions via a RAG agent with timestamp and key-frame references. Configurable vision model and LLM for future switching."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 上传视频并获取课程总结 (Priority: P1)

学习者下载了一门技术慕课到本地，希望系统能自动整理出课程结构和核心内容，节省手动做笔记的时间。

**Why this priority**: 这是产品最核心的价值交付点。没有总结功能，后续问答和学习都无从谈起。

**Independent Test**: 用户上传一个 5-40 分钟的本地视频后，可以在界面上看到课程大纲、内容摘要和详细讲义，且处理状态可见。

**Acceptance Scenarios**:

1. **Given** 用户进入课程库页面，**When** 用户选择本地视频并上传，**Then** 系统显示处理进度，并在完成后展示课程卡片。
2. **Given** 一个课程已完成处理，**When** 用户点击课程卡片，**Then** 系统展示该课程的大纲、摘要和讲义三个层级内容。
3. **Given** 上传的视频画面包含图表、公式或代码，**When** 系统生成总结，**Then** 讲义中应包含这些视觉信息的关键描述，不遗漏核心知识点。
4. **Given** 处理过程中某一步失败，**When** 用户查看课程状态时，**Then** 系统显示失败原因并允许用户重新处理。

---

### User Story 2 - 基于课程内容进行知识问答 (Priority: P2)

学习者在看完课程后，对某个概念或实现细节有疑问，希望系统能基于课程内容给出准确回答，并指出该内容在视频中的位置。

**Why this priority**: 问答是智能总结的自然延伸，能显著加深学习效果，也是区别于普通视频播放器的关键能力。

**Independent Test**: 用户在问答页面选择一门已处理课程并提问，系统返回的答案必须基于课程内容，并附带相关时间戳和关键帧画面。

**Acceptance Scenarios**:

1. **Given** 一门课程已完成处理，**When** 用户在问答页面输入与课程相关的问题，**Then** 系统返回答案并列出相关时间戳。
2. **Given** 系统返回答案，**When** 答案涉及视频画面内容，**Then** 系统展示最相关的关键帧缩略图。
3. **Given** 用户输入与课程内容无关的问题，**When** 系统无法找到相关内容，**Then** 系统明确告知用户该问题不在课程内容范围内。
4. **Given** 用户点击答案中的时间戳，**When** 用户进入课程学习页面，**Then** 视频自动跳转到对应时间点。

---

### User Story 3 - 在视频学习页面中定位知识点 (Priority: P3)

学习者在复习时，希望对照视频画面查看大纲和讲义，并通过时间戳快速跳转到关键片段。

**Why this priority**: 提升学习效率，让用户从“看完总结”自然过渡到“回到原视频复习”。

**Independent Test**: 用户在课程学习页面播放视频时，可以看到大纲和讲义，点击任意时间戳后视频跳转到对应位置。

**Acceptance Scenarios**:

1. **Given** 用户进入课程学习页面，**When** 页面加载完成，**Then** 视频播放器、大纲、摘要、讲义同时可见。
2. **Given** 用户在大纲中点击某一章节，**When** 用户触发跳转，**Then** 视频播放器跳转到该章节对应时间戳。
3. **Given** 用户在问答页面点击时间戳，**When** 用户进入学习页面，**Then** 视频从该时间戳开始播放。

---

### Edge Cases

- 上传非视频文件或损坏的视频文件时，系统应提示用户并拒绝处理。
- 视频无音频或音频无法识别时，系统应继续基于画面内容生成总结，并记录警告信息。
- 视频画面无文字或视觉内容为空时，系统应基于音频字幕生成总结，不阻塞整体流程。
- 单课程时长超过 40 分钟时，系统按最大采样上限处理，保证成本和性能可控。
- API 调用失败或限流时，系统应记录错误并允许用户重试，而不是无限等待。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须允许用户从本地上传视频文件（支持 MP4、MKV、MOV 等常见格式）。
- **FR-002**: 系统必须对上传的视频进行多模态处理，包括音频转写、关键帧抽取、帧内文字识别和画面内容理解。
- **FR-003**: 系统必须基于处理结果生成三级总结：课程大纲、内容摘要和详细讲义。
- **FR-004**: 系统必须支持用户针对已处理课程进行知识问答，回答内容必须严格基于课程内容。
- **FR-005**: 系统在回答问题时必须提供相关时间戳，并在涉及画面内容时展示关键帧。
- **FR-006**: 系统必须提供视频播放页面，支持通过大纲、摘要、讲义或问答结果中的时间戳跳转。
- **FR-007**: 系统必须记录课程处理状态，并在界面上向用户展示当前进度或失败原因。
- **FR-008**: 系统必须支持通过配置切换视觉理解模型和问答模型，避免单一供应商锁定。
- **FR-009**: 系统必须持久化课程元信息、字幕、帧信息、总结内容和问答历史。
- **FR-010**: 系统必须针对中文课程内容进行优化，包括中文语音识别、中文 OCR 和中文语义检索。

### Key Entities

- **Course（课程）**: 用户上传的视频及其处理结果，包含标题、时长、处理状态、创建时间等元信息。
- **Transcript（字幕）**: 从视频音频中提取的文本内容，按时间分段，包含开始时间和结束时间。
- **Frame（关键帧）**: 从视频中抽取的图像帧，包含时间戳、OCR 文字、画面描述和缩略图路径。
- **Summary（总结）**: 针对课程生成的大纲、摘要和讲义内容。
- **ChatMessage（问答消息）**: 用户在问答页面提出的问题及系统返回的答案，包含引用的来源信息。
- **Progress（学习进度）**: 用户在课程学习页面最后观看到的时间点。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从上传视频到看到完整总结的处理时间不超过视频时长的 2 倍（例如 40 分钟视频在 80 分钟内完成）。
- **SC-002**: 生成的总结必须覆盖视频中 80% 以上的核心知识点（通过抽样检查关键片段验证）。
- **SC-003**: 针对课程内容提出的问题，80% 以上的回答能够附带正确的时间戳定位。
- **SC-004**: 用户可以在 3 次点击以内从问答结果跳转到视频对应位置。
- **SC-005**: 系统处理 10 门标准长度（40 分钟）课程的月度外部 API 成本控制在 100 元人民币以内。
- **SC-006**: 核心处理链路（上传 → 转写 → 抽帧 → 总结 → 问答）可以通过 quickstart 文档中的步骤在 30 分钟内完成环境搭建并跑通示例。

## Assumptions

- 用户上传的视频为本地文件，MVP 阶段不支持直接从慕课平台 URL 下载或浏览器录屏。
- 用户具备基本的本地开发环境配置能力，能够安装 ffmpeg 等系统依赖。
- 用户拥有自己的外部模型 API Key，MVP 阶段不提供共享 API 额度。
- 课程以中文讲解为主，系统针对中文优化，但也能处理中英混合内容。
- MVP 阶段为单用户本地使用，暂不考虑多用户并发和云端部署。
- 视频分辨率足以让 OCR 和视觉模型识别画面中的文字和图表。
