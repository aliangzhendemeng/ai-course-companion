# Feature Specification: 004 - 多课程学习集与使用门槛优化

**Feature Branch**: `004-multi-course-sets`

**Created**: 2026-07-29

**Status**: Draft

**Input**: User description: "第四版：新增多课程学习集（用户只想针对某几门课学习，例如上传了数学/英语/语文多个视频后，只学数学的某几节课），并延续降低使用门槛的规划（一键启动、设置页完善、桌面 App）。"

---

## 背景

003 迭代 1（学生体验优化 US1-US6 + 导航）已完成。当前问答只有两档范围：

- **单课程**：`/courses/{id}` 内针对当前课提问（走该课完整清洗文本）。
- **全部课程**：全局搜索跨所有课程提问（`query_all`）。

用户提出新需求：希望能在"单课程"和"全部课程"之间，自由选择**某几门课**组成的学习范围。典型场景：上传了数学、英语、语文多门课的多个视频后，只想针对"数学的某几节课"学习提问，排除无关课程干扰。

技术可行性已确认：所有课程的字幕/帧均索引在全局向量库，文档 metadata 带 `course_id`；`RAGEngine.query_all` 已实现跨课程检索 + 多课全文拼接。因此多课程范围本质是**给全局检索加课程过滤**，后端改动可控。

---

## 用户场景与测试

### User Story 1 - 多课程学习集（命名收藏夹）（Priority: P1）

学生可以把若干门已完成课程保存为一个命名的"学习集"（如"数学必修"），之后针对该集合提问；学习集可复用、可管理（重命名/增删课程/删除）。

**Why this priority**: 这是本版核心新需求，直接解决"只想学某几门课"的痛点。相比"临时多选"（方案 A），命名收藏夹（方案 B）更贴合用户"反复针对固定几节课学习"的真实场景。

**Independent Test**: 创建学习集"数学"并勾选 2 门数学课，提问后答案只基于这 2 门课；来源只来自这 2 门课且可跳转。

**Acceptance Scenarios**:

1. **Given** 课程库有多门已完成课程，**When** 用户在问答入口选择"选择课程/学习集"并勾选 2 门课保存为"数学"，**Then** 学习集被持久化，列表中可看到"数学（2 门课）"。
2. **Given** 用户选中学习集"数学"，**When** 提问一个该集合内的问题，**Then** 后端只在这 2 门课的索引内检索并拼接这些课的全文回答，答案不引用其他课程。
3. **Given** 回答产生来源，**When** 用户查看来源，**Then** 每条来源带课程名 + 真实时间戳，点击可跳转到对应课程对应时间点。
4. **Given** 用户已有学习集，**When** 重命名 / 增删课程 / 删除学习集，**Then** 变更即时生效并持久化。
5. **Given** 学习集内某门课被删除或重新处理，**When** 再次提问，**Then** 系统能优雅处理缺失课程（跳过或提示），不报错。

---

### User Story 2 - 一键启动脚本（Priority: P1）

学生双击一个脚本即可同时启动后端与前端并自动打开浏览器，退出时一并关闭。

**Why this priority**: 当前需分别启动后端 `run.py` 和前端 `npm run dev`，对非技术学生门槛过高。规划中原定为"下一版本优先"。

**Independent Test**: 在干净终端运行 `start_app.sh`，浏览器自动打开可用界面；Ctrl+C 后前后端进程都退出。

**Acceptance Scenarios**:

1. **Given** 后端依赖已安装，**When** 运行启动脚本，**Then** 后端与前端同时启动，自动打开浏览器到正确端口。
2. **Given** 应用已在运行，**When** 用户 Ctrl+C 或关闭脚本，**Then** 前后端进程一并终止，不留残留进程占用端口。
3. **Given** 端口被占用，**When** 启动脚本，**Then** 给出清晰提示（哪个端口被占、如何处理），而不是堆栈报错。

---

### User Story 3 - 设置页完善与首次引导收尾（Priority: P2）

完善 003 已搭好的设置页骨架：首次使用引导、保存后生效提示（需重启或热加载）、默认值与 Key 回退。

**Why this priority**: 003 已建立 settings 页 + 后端接口骨架，本版补完体验闭环。

**Independent Test**: 清空 API Key 首次打开，进入引导页配置后正常使用；修改 Key 后有明确生效提示。

**Acceptance Scenarios**:

1. **Given** 用户首次访问且未配置 Key，**When** 打开应用，**Then** 自动进入欢迎/配置引导页，显示默认推荐模型。
2. **Given** 用户在设置页保存配置，**When** 配置写入 `.env` 且未实现热重载，**Then** 明确提示"需重启后端生效"。

---

### User Story 4 - 桌面 App 包装（Priority: P3）

用 Tauri 或 Electron 打包前后端，学生双击即用，应用内自动启动后端。

**Why this priority**: 完全无门槛，但工程量与维护成本最高，放在本版最后或下版。

**Independent Test**: 打包产出可执行文件，双击后无需命令行即可使用完整功能。

---

## 功能需求

- **FR-1**: 系统 MUST 提供学习集的创建、查看、重命名、增删课程、删除能力，并持久化（新增数据表：学习集 id / name / 关联 course_ids）。
- **FR-2**: `ChatRequest` MUST 支持可选 `course_ids`（学习集展开后的课程集合）。
- **FR-3**: `RAGEngine` MUST 新增 `query_multiple(course_ids, question)`：在全局向量/BM25 检索时按 `course_id` 过滤，命中课后拼接这些课的全文回答（复用 `query_all` 多课拼接逻辑）。
- **FR-4**: 多课程回答的来源 MUST 带课程名与真实时间戳，前端可点击跳转到对应课程时间点。
- **FR-5**: 学习集内课程缺失（被删/重处理中）时，系统 MUST 优雅降级（跳过并提示），不报错。
- **FR-6**: 前端 ChatPanel scope 选择器 MUST 增加"选择课程/学习集"入口，弹出多选/学习集选择界面。
- **FR-7**: 系统 MUST 提供一键启动脚本，同时启动前后端、自动打开浏览器、退出时一并关闭。
- **FR-8**: 设置页保存后若未热重载，MUST 提示需重启后端。

---

## 成功标准

- **SC-1**: 用户能在 3 步内创建一个学习集并完成一次限定范围的提问，答案与来源均只来自所选课程。
- **SC-2**: 多课程问答来源 100% 带课程名与可跳转时间戳。
- **SC-3**: 一键启动脚本在干净环境下一次成功启动并自动打开浏览器。
- **SC-4**: 非技术用户无需编辑 `.env` 或命令行即可完成配置与启动。

---

## 边界 / 非目标

- 学习集不含权限/多用户隔离（单用户本地应用）。
- 本版不改变单课程与全局搜索的现有行为，仅新增"多课程"档位。
- 桌面 App 包装（US4）可在本版内裁剪，视工程量决定是否延后。

---

## 假设

- 全局向量库文档 metadata 均含 `course_id`（当前已满足）。
- 学习集与课程的关联为"多对多"，课程删除时关联随之失效。
- 多课程全文拼接需控制上下文长度，超限时回退到片段检索。
